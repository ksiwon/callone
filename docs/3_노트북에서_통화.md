# 3. 노트북에서 clone과 통화하기

> 학습 끝난 모델로 **노트북에서 실시간 통화**. 대상: Intel Arc iGPU(예: 갤럭시북5 Pro / Arc 140V).
> 스택: **EXAONE-3.5-2.4B + LoRA(말투) → OpenVINO int4(Arc, 권장) 또는 llama.cpp GGUF + Piper(화자 목소리, onnx) + faster-whisper(ASR)**.
>
> 왜 EXAONE-2.4B? 서버(7.8B)와 같은 LG 한국어 특화 계열의 경량본 → 말투·한국어 일관. 2.4B int4 ≈ 1.5GB 로
> Arc iGPU 에 가뿐(7.8B 대비 빠른 토큰레이트). **폰 온디바이스 경로는 폐기 — 노트북만 지원.**

준비물(서버/GPU에서 만든 산출물):
- LoRA 어댑터: `models/llm_laptop/{A,B}/` (말투 학습본; `adapter_config.json` 있는 곳)
- 페르소나·RAG: `data/speakers/{A,B}/` (profile.json, utterances.json)
- 화자 목소리: `models/tts_piper/{A,B}.onnx` (+ `.onnx.json`) — [5. 화자 A 목소리 학습](5_화자A_목소리_학습.md)

---

## 경로 A (권장·최적): OpenVINO int4 — Arc iGPU 네이티브
EXAONE 은 표준 아키텍처라 OpenVINO 변환이 되어, Arc iGPU 에서 **네이티브 int4**로 가장 빠르다.

```powershell
pip install "optimum-intel[openvino]" peft transformers
# LoRA 병합 + OpenVINO IR(int4) 변환 → models_ov/exaone-2.4b-int4 (또는 화자별)
python scripts\merge_to_ov.py --speaker A --bits int4
```
- 결과를 `models/llm_ov/A` 또는 `models_ov/exaone-2.4b-int4` 에 두면 `OVPersonaLLM` 이 자동 인식.
- `configs/llm_laptop.yaml` 의 `device: GPU`(Arc) 로 구동. 변환이 막히면 경로 B 로.

## 경로 B (대안): llama.cpp GGUF — Vulkan
OpenVINO 변환이 안 되거나 CPU 폴백이 필요할 때.

### 1) llama.cpp 받기 (1회)
- **바이너리**: GitHub Releases 의 `llama-bXXXX-bin-win-vulkan-x64.zip` → `C:\tools\llama.cpp\`
- **소스(변환 스크립트용)**: `git clone https://github.com/ggml-org/llama.cpp C:\tools\llama.cpp-src`

### 2) LoRA → 단일 GGUF (1회) — `scripts/make_gguf.py`
LoRA를 base에 **병합**해 GGUF로 굽는다.
```powershell
pip install torch peft "transformers>=5.10"
# fp16 base 받기(병합에 필요, 1회)
hf download LGAI-EXAONE/EXAONE-3.5-2.4B-Instruct --local-dir models_base\exaone-2.4b
# 병합 → f16 GGUF
python scripts\make_gguf.py --speaker A --base models_base\exaone-2.4b `
    --llama-cpp C:\tools\llama.cpp-src --quant f16 --keep-merged
# Q4 양자화(속도)
C:\tools\llama.cpp\llama-quantize.exe models_gguf\exaone-2.4b-A-f16.gguf `
    models_gguf\exaone-2.4b-A-Q4_K_M.gguf Q4_K_M
```
→ 배포 모델 `models_gguf\exaone-2.4b-A-Q4_K_M.gguf` (~1.5GB). 끝나면 base/f16/merged는 지워도 됨.

### 3) llama-server 띄우기 (별도 터미널, 통화 중 계속 켜둠)
```powershell
$env:GGML_VK_DISABLE_COOPMAT = "1"      # Arc 140V Vulkan TDR 회피
C:\tools\llama.cpp\llama-server.exe -m models_gguf\exaone-2.4b-A-Q4_K_M.gguf `
    -ngl 99 -c 4096 --host 127.0.0.1 --port 8080 --jinja
```
- GPU 불안정하면 `-ngl 0`(CPU, 안 죽지만 느림). 더 빠른 SYCL은 Intel IPEX-LLM llama.cpp 포터블.
- `http://127.0.0.1:8080/health` 가 `ok` 면 준비됨.

## 화자 목소리 배치
`models/tts_piper/A.onnx` + `A.onnx.json` 두면 자동 인식. 없으면 placeholder(beep)로 폴백(루프 확인용).
```powershell
pip install piper-tts sounddevice      # Piper 추론 + 마이크
```

## 통화
**A. 간단 — 마이크 CLI**
```powershell
python scripts\call_mic.py --speaker A
# [Enter] 누르고 말하기 → 끝나면 [Enter] 다시 → 화자 A 응답(목소리)
```
**B. 브라우저 UI**
```powershell
callone-serve          # 터미널1: http://localhost:8000 (llm.backend=auto → OV/8080 자동 감지)
cd ui && npm install && npm run dev    # 터미널2: http://localhost:5173
```

## 동작 / 튜닝
- 흐름: 마이크 → faster-whisper(한국어) → **EXAONE-2.4B+LoRA(화자 말투)** → Piper(화자 목소리) → 스피커.
- 설정은 `configs/llm_laptop.yaml` · `configs/serve.yaml` `llm:` 에서:
  - `temperature: 0.4`, `max_new_tokens: 96` — 전화 톤(짧고 덜 산만, 한국어 문법 안정). 서버 EXAONE 와 동일 기조.
  - `use_rag: false` (기본) — LoRA가 말투 내재화 → 일상대화엔 RAG 끄는 게 자연스러움. 사실 기억 필요하면 `true`.
- ASR이 CPU라 느리면 `asr.model: small` 로 낮추면 빨라짐(정확도 약간↓).

## 빠른 점검(LLM만, 경로 B)
```powershell
$body = @{messages=@(@{role='user';content='화자 A 나 왔어'});max_tokens=80} | ConvertTo-Json -Depth 6
$bytes=[Text.Encoding]::UTF8.GetBytes($body)
(Invoke-RestMethod -Uri http://127.0.0.1:8080/v1/chat/completions -Method Post -ContentType 'application/json; charset=utf-8' -Body $bytes).choices[0].message.content
```
화자 말투(예: 경상도 "마/~노/~나/아이가")가 나오면 LoRA 적용 성공.
