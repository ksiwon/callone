# 먼저 읽기 — 어떤 버전을 고를까

이 안에는 두 개의 폴더가 있습니다. **둘 다 처음부터 설치하는 버전**이고, 앱 자체
(`app_studio.py`)는 동일합니다. 차이는 설치 방식뿐입니다.

| | GPU 버전 (`GPU_A100/`) | CPU 버전 (`CPU_laptop_WSL2/`) |
|---|---|---|
| 실행 환경 | Elice 등 A100 인스턴스(리눅스+CUDA) | 갤럭시북5 + Windows + WSL2 |
| 난이도 | **쉬움 (강력 추천)** | 하드 모드 |
| 속도 | 빠름(문장당 수 초) | 합성 문장당 ~30초(CPU 8스레드, RTF~10) |
| 흔한 함정 | 거의 없음 | dtype·torchaudio 등 환경 민감 |
| 결과 품질 | 동일 | 동일 |

- 결과물은 어차피 다운로드해서 쓰시므로, **가장 덜 고생하고 30배 빠른 길은 GPU(A100)** 입니다.
- 노트북만으로 끝내고 싶으면 CPU 버전을 쓰세요. **실측상 갤럭시북5에선 CPU 8스레드가 최速**입니다 —
  Arc 140V iGPU(XPU)도 시도했으나 자기회귀 TTS 라 오히려 더 느렸습니다(자세한 건 CPU 폴더의 README).

## 공통 동작
- ① 만들기: WAV 업로드 → 자동 전사(틀리면 직접 수정) → 후보(원본/디노이즈) 생성 →
  가장 본인 같은 것 선택 → 이름 붙여 저장
- ② 사용하기: 저장한 목소리 선택 → 한국어 텍스트 입력 → 합성 → 듣기/다운로드
- 학습/대기 없음(제로샷). "저장"되는 건 학습 모델이 아니라 음성 프로필입니다.

각 폴더 안의 `README_*.md` 에 단계별 설치·실행법이 있습니다.

## 유사도 팁 (둘 공통)
- 잡음 없는 또렷한 5~10초 WAV를 쓰세요.
- 전사를 실제 발화와 글자까지 일치시키면 유사도가 가장 좋아집니다.
- 향상이 항상 좋은 건 아닙니다 — **원본 후보와 꼭 비교**해서 본인 귀에 더 똑같은 걸 고르세요.
